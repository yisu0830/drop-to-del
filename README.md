# Drop to Del · 桌面碎纸机

[简体中文](#简体中文) · [English](#english)

## 简体中文

Drop to Del 是一台放在 Mac 桌面上的像素碎纸机。把项目文件夹拖进来，它帮你找出 AI 开发过程中留下的测试截图、预览图和检查报告；把 App 拖进来，它会连同应用副本、可能的安装包和散落在用户资源库里的相关文件一起列出来，让你决定清哪些。

### 为什么做它

我和 AI 一起做项目时，经常让它改完页面后跑一遍，截张图给我看。改到第五版，第一版的截图还躺在文件夹里。项目交付了，那些截图、预览和测试时生成的文件也跟着留了下来。

我以前做过电脑清理，发现这些文件的命名和存放位置往往有规律。于是我做了 Drop to Del，让它先把可能用完的东西找出来，我只需要看一眼清单，决定哪些还值得留。

### 拖一个项目，整理开发现场

扫描结果按类别列出。你可以看到文件大小，点放大镜在 Finder 里核对原文件，再按项或整组勾选。

- **测试截图和预览图**：按命名规则找出可能的过程截图，也能识别 HyperFrames 项目生成的预览缩略图。待确认的图片默认不勾选，方便你留下要交付的素材。
- **过程检查文件**：结合项目里的交付说明，识别用于检查的中间产物，例如已经完成使命的报告。
- **项目依赖和隐藏文件**：列出含有 `package.json` 的项目里的 `node_modules`，以及 Finder 留下的 `.DS_Store`。依赖目录默认不勾选，归档旧项目时可以按需清理。

### 拖一个 App，连同关联文件一起清理

卸载应用时，下载目录里可能还留着安装包，用户资源库里也可能存着缓存、日志和偏好设置。把 `.app` 拖进碎纸机，就能在一张清单里核对这些位置：

- 查看应用本体、随它一起移走的内置组件，以及具有相同 Bundle ID 的其他副本。
- 查看按文件名匹配出的安装包，核对路径，决定要不要保留。
- 按应用或内置组件的 Bundle ID 查找用户资源库中的缓存、日志、偏好设置、应用支持文件和容器数据。

应用清单默认勾选全部候选项。取消勾选想保留的副本或数据，再点「移到废纸篓」。清单会像一张小纸条一样送进机器，碎成纸屑落下来。实际文件进入 macOS 系统废纸篓，清空前可以找回。

### 下载与安装

从[发布页](https://github.com/yisu0830/drop-to-del/releases)下载适合你 Mac 的 ZIP 文件。Apple 芯片选 `arm64`，Intel 芯片选 `x86_64`。解压后，将 **Drop to Del.app** 拖入「应用程序」文件夹。需要 macOS 14 或更高版本，应用界面为简体中文。

发布版采用 ad hoc 签名，尚未经过 Apple 公证。如果 macOS 阻止首次启动，请在尝试打开后前往「系统设置 → 隐私与安全性」，查看是否有「仍要打开」选项。

### 从源码构建

在 macOS 14 或更高版本上安装 Xcode 命令行工具，然后运行：

```sh
bash Scripts/build.sh
```

构建好的应用和 ZIP 文件位于 `build/<architecture>/`。可通过 `ARCH=arm64` 或 `ARCH=x86_64` 指定目标架构。

## English

Drop to Del is a little pixel-art shredder that sits on your Mac desktop. Drop a project folder onto it to find test screenshots, previews, and reports left over from working with AI. Drop an app onto it to find other copies, possible installers, and related files in your user Library. You choose what goes in the Trash.

### Why I built it

When I build a project with AI, I often ask it to run the page it just changed and take a screenshot. By the fifth revision, the screenshot from the first one is still sitting in the folder. Even after I ship the project, those screenshots, previews, and test files stick around.

I used to work on computer cleanup tools, so I noticed a pattern in the names of these files and where they ended up. I built Drop to Del to find the likely leftovers and give me a short list to review.

### Drop a project folder to tidy up after development

The scan groups files by type and shows their sizes. Click the magnifying glass to reveal a file in Finder, then select individual items or a whole group.

- **Test screenshots and previews.** Drop to Del uses filename patterns to flag possible test screenshots. It also recognizes preview thumbnails generated by HyperFrames projects. Images that need your judgment start unchecked so you can keep the ones you plan to deliver.
- **Review files.** The scanner uses the project's delivery notes to identify intermediate files such as reports generated during review.
- **Dependencies and hidden files.** It lists `node_modules` folders alongside a `package.json`, as well as the `.DS_Store` files Finder creates. Dependency folders start unchecked, so you can choose to clear them when archiving an old project.

### Drop an app to clean up its related files

An installer can linger in Downloads, while caches, logs, and preferences live elsewhere in your user Library. Drop a `.app` onto the shredder to review them together.

- See the app itself, the bundled components that go with it, and other copies with the same bundle ID.
- Review possible installers matched by filename and check their locations before deciding which to keep.
- Find caches, logs, preferences, application support files, and container data associated with the bundle ID of the app or one of its components.

All candidates in an app scan start selected. Uncheck any copies or data you want to keep, then click **移到废纸篓** (Move to Trash). The list slips into the shredder like a paper receipt and comes out as confetti. The selected files go to the macOS Trash, where you can recover them until you empty it.

### Download and install

Download the ZIP for your Mac from the [Releases page](https://github.com/yisu0830/drop-to-del/releases), unzip it, and move **Drop to Del.app** to **Applications**. Drop to Del requires macOS 14 or later. Choose `arm64` for Apple silicon or `x86_64` for Intel.

The release is ad hoc signed and has no Apple notarization. If macOS blocks the first launch, open **System Settings → Privacy & Security** after attempting to open the app and check for **Open Anyway**. The current interface is in Simplified Chinese.

### Build from source

On macOS 14 or later, install Xcode Command Line Tools and run:

```sh
bash Scripts/build.sh
```

The app and ZIP are written to `build/<architecture>/`. Set `ARCH=arm64` or `ARCH=x86_64` to select a target.
